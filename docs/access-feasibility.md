# Stage 0 access feasibility

Verified 2026-10-20. These findings describe access routes and bounded probes, not an operating campus tracker. Public vendor metadata, a documentation page, or an FSU directory link does not establish successful event ingestion. See `evidence/` for actual local probe outcomes and `config/social-pilot-accounts.json` for the 39-account pilot roster.

## FSU HQ / CampusGroups

The [FSU FAQ](https://studentaffairs.fsu.edu/fsu-hq-faq) says HQ replaces NoleCentral and restricts full login to current Main/Panama City students and active employees. This project has no authorized HQ session or private export credential. Do not request, save, or automate the user's FSUID password. A successful public HQ page cannot establish full-campus access.

**Verified public export:** the public HQ events page exposed [the institution ICS link](https://hq.fsu.edu/ical/floridastate/ical_floridastate.ics). Its observed 302 points to [the CampusGroups static export](https://static-prod-us-east-1.campusgroups.com:443/ical/floridastate/ical_floridastate.ics). An exact-path read returned **HTTP 200, 1,119,964 bytes, 1,146 VEVENT records and 1,146 unique UIDs**; 441 starts were on/after 2026-10-20. Observed starts span 2026-07-22 through 2027-05-26; no RRULE appeared in that sample. Evidence: `reports/probes/hq-export-redirect.json`. The payload had DTSTAMP/modified metadata, ETag and Last-Modified, but no actual edit/cancellation or completeness was proven. This is a working public HQ intake candidate with measured sample scope; full/member-only visibility, feed truncation and update semantics remain unknown. RSVP-shaped links were evidence only, never followed as actions. No password or session was used.

The [vendor events guide](https://helpcenter.readyeducation.com/exploring-and-attending-events) documents **Events → Subscribe to group event calendars / sync calendars**. The preferred student-access investigation is for an eligible user to use normal FSU SSO themselves, inspect these controls, and provide a supported event-calendar subscription only if its permitted use is confirmed. Treat a private feed URL as a bearer secret in the server secret store. Determine selected groups, membership/visibility restrictions, date horizon, UID/update/cancellation behavior, and whether subscription authorization survives membership changes. FSU's availability of these controls is untested. A subscription is intake evidence; it must never be directly subscribed into the user's real calendar or bypass occurrence-by-occurrence approval.

The [CampusGroups API documentation](https://www.campusgroups.com/api?public=1) separately documents institutional integrations. Its RSS APIs require `X-CG-API-Secret`; the event route is `/rss_events`. The generic URL contains legacy `ts`/`preauth` parameters; use the exact institution-approved configuration, not guessed FSU credentials. The event schema includes `eventUid`, `dateUpdated`, `eventDelete`, and visibility fields distinguishing everyone, logged-in users, group members, eligible registrants, and hidden events. Its creation APIs separately document an administrative school code/key setup. **Student SSO does not grant institutional API credentials.**

The precise permissioned path for broader HQ access is an FSU HQ administrator's event-only export/integration provision, scoped to records the user is allowed to see, with written allowed use, retention and revocation terms. Ask for an administrator-supplied feed/endpoint and read secret with event identifiers, dates, time zones, updates/deletes, visibility, organizer and action links. Do not call user, roster, transaction or attendee endpoints. Private/institutional export availability, exact permissioned FSU endpoint, permission, pagination/update coverage and price remain unverified. No request was sent to FSU. The public central-calendar HQ department is a supplemental source; neither it nor the verified public ICS is a proven full HQ mirror.

Keep the collector interface vendor-neutral: source identity, native ID, publication/fetch/first-seen times, event-relevant caption, ordered media/children, links, error/rate-limit status, and per-run charge breakdown. A future provider must implement the same completeness and failure contract. Do not let actor-shaped output become the domain schema. A community actor disappearing must degrade source health, not erase the catalog.

`social_probe.py` has fixed HTTPS read paths. It cannot start actors, including Apify's billable convenience **GET** endpoints. Public metadata reads are live; `apify-dataset` can inspect only an already authorized dataset when configured. Dataset retrieval is not proof that this project ran a collector. It preserves empty/error rows rather than requesting `clean=true`, limits pages, detects error envelopes, suppresses exception bodies and follows no redirects that could leak bearer tokens. No media is downloaded. Exit 2 means setup-needed; exit 3 means blocked/partial/unverified empty. Neither means “nothing new.”

## Seven-day public-social pilot: specified, not authorized or run

Use the **39 actual organizer accounts** extracted from the [official FSU directory](https://studentaffairs.fsu.edu/resources/social-media-follow-list); the list is in `config/social-pilot-accounts.json`. Affiliation links were verified, but current account existence/public status/professional type were not. Before starting, validate each handle, allowed access and account type; exclude inaccessible accounts with an explicit denominator change. Keep 30–50 eligible accounts, retaining arts, social/culture, recreation/outdoors, general student life, research/academic and career categories. This roster is heavily institutional; small independent clubs and consumer profiles are an **unverified stratum**, not represented coverage. Before launch, add/replace at least five small-club accounts with permitted access and verified official affiliation links (e.g. supplied through supported HQ/organization websites), recording professional versus consumer status; if unavailable, mark that stratum unmeasured. Directory staleness remains a gap. Any replacement account needs an official affiliation link and an updated cost calculation.

1. **Preflight:** user-approved future spend ceiling and permitted use; token/vendor account; read current input schemas/pricing again; pin actor/build; record per-account public/permissioned status. `config/social-pilot-supplement.json` supplies five student-run arts-club **replacement candidates** linked in the official 2024–25 handbook: archived affiliation only, with current handle ownership/type/content access untested. Reverify before replacing five institutional accounts in the 39-account baseline; additions would create 44 accounts and require recalculation (`python3 scripts/cost_model.py --accounts 44`). They are not an operational small-club stratum. No private accounts, session-cookie sharing, password collection, CAPTCHA bypass or member-only scraping. Read vendor and platform terms; vendor marketing is not permission. For organizer-owned official APIs, use consent and least privileges. If terms/permission cannot support the vendor route, leave it disabled and test authorized submissions instead.
2. **Collection schedule:** one batched check of up to 50 accounts every six hours for posts (4/day), one batch every two hours for Stories (12/day). Run post backfill once, up to 12 items/account; this is an item cap, not a guaranteed 60–90-day history. Request detailed post data and all media; disable music data. Use [post input fields](https://apify.com/apify/instagram-post-scraper/input-schema) `username`, `resultsLimit`, `dataDetailLevel="detailedData"`, `includeMusicData=false`. [Story input](https://apify.com/datavoyantlab/advanced-instagram-stories-scraper/input-schema) uses `usernames`, max 100; configure only the audited 39. No Story backfill promise. These are a future execution specification; this repository intentionally contains no actor-starting function.
3. **Ground truth:** at 09:00, 13:00, 17:00 and 21:00 America/New_York each day, an authorized human records visible new posts/each carousel slide/Stories with native ID or stable URL, observed time, visible publication time when available, media count, opportunity/action labels, and access errors. Archive only permitted event-relevant evidence privately. Manual observation budget is assumed 3 minutes/account/day (13.65 hours/7 days), to be measured and increased if insufficient. Mark unaudited account/windows and removed content as unobserved, not successes or negatives. Do not infer the full campus or all-Story denominator from these checks.
4. **Compare:** report captured/observed accessible posts and Stories separately, full-carousel captures/observed carousels, accessible ordered media items returned/observed media items, confirmed new opportunities beyond calendar sources, median/P95 publication→first-seen where timestamps exist, fetch→extraction delay, error and silent-empty rate, per-account failures, empty checks and all actual billable events/bytes/model tokens. A zero observed denominator is “not measured.” Reconcile a vendor empty list against the same account's manual window; error/login/expired token/timeout is a failed run, never a negative observation. Keep duplicate item charges separate from unique captures.
5. **Promotion gate:** ≥95% observed accessible-post capture, ≥95% complete observed carousels, ≥90% observed accessible-Story capture, no known silently swallowed errors; all failures classified; latency reported over audited windows; actual spend within the separately approved cap. These are proposed project gates, not measured performance. Report numerator, denominator, excluded accounts/windows and sample size beside every rate; require more sampling if fewer than 20 carousels/20 Story-bearing account-windows are observed. Story deletion between observations and overnight gaps remain unknown. Promote each route separately; failure of Stories need not block useful posts or core sources.

The reproducible cost forecast is **$41.15 incremental** for the 39-account pilot under stated assumptions (including repeated-post billing, Story start fees, a retry reserve, model work and $3 storage/transfer reserve). Proposed ceiling: **$45**, unapproved. Core hosting, taxes, human labor and extra unmeasured vendor charges are excluded. These numbers are not an invoice, purchase or permission to run. See `docs/cost-model.md` and rerun `python3 scripts/cost_model.py` after account/cadence/price changes. At 80% of a future approved cap, report and reduce expensive work; at 100%, halt paid collectors and retain source-health reporting. Initial max charge controls must be set on each future run as well as a durable project ledger; billed retries and empty checks count.

## Other social and shared-lead routes

[Sidechat/Yik Yak terms](https://sidechat.notion.site/Sidechat-Terms-of-Use-d2f718ddad2f403b85bba67078fbdf18), section 1.3, prohibit scraping/downloading through automated or manual scraping processes. No supported public developer API was established. **Yik Yak remains manual/shared-lead only:** a user may supply an event lead/link they are allowed to share; corroborate with an organizer/public event source, minimize identifying content and never automate collection or mirror the conversation. Sharing a lead is not a license to copy a private thread.

Facebook public Page access remains permission/app-review dependent; no Group connector is proposed. The pack's Groups API removal reference was not independently retrieved here, so Stage 0 makes no operational Facebook claim. [GroupMe bots](https://dev.groupme.com/tutorials/bots) and [Discord bot rules](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots) are future organizer-approved announcement routes; a normal user's membership is not authorization to install a collector or use a self-bot.
