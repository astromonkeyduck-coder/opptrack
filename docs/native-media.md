# Native private-media processing

`lib/extraction/media.ts` is a worker-only byte processor. It receives private Storage bytes and stable asset IDs, verifies their original SHA-256 hashes, and returns ordered evidence units. It has no URL-fetch function, database client, model credential, calendar executor, delivery client or shell interpreter. Source text is evidence only. Native subprocesses receive a minimal PATH/locale/thread environment, never inherited service credentials.

Images pass MIME/signature, decoded-pixel and frame checks, then Sharp normalizes them to a bounded PNG. Tesseract's English LSTM OCR produces TSV word boxes. The text is reconstructed from actual OCR lines; word coordinates refer to the normalized image. OCR confidence is not a factual confidence score and is not used to approve facts or actions.

For PDFs, `pdfinfo` records the page count. Every known page repeats that original count as `expectedPages`, allowing downstream validation to require the complete consecutive page range and detect a lost final page. Encrypted or copy-restricted files are blocked without password attempts or overrides. Every bounded page receives both a Poppler text pass and a rendered visual OCR pass; a nonempty text layer does not skip an embedded image-only flyer. Differences between text and visual text remain issues. If rendering or OCR fails, any bounded text-layer evidence remains attached to a failed page and the job stays incomplete. Successful empty OCR is reported separately from native-process failure.

The fixed job limits are eight assets, 4 MiB combined bytes, 12 visual units, 12 million decoded image pixels, a 2000-pixel rendered long edge, 20 seconds per subprocess, 120 seconds total, bounded stdout/text/word counts and one native OCR thread. A database-granted `maxVisualPages` may narrow the visual limit to zero through 12; it cannot raise it. Each rejected asset and every known PDF page up to the bounded manifest limit has an explicit failed/blocked outcome. Extreme PDF page counts are blocked as whole assets rather than allocating an unbounded page list. `complete` means processing coverage of supplied units, not that every visible word or event was correctly understood. Unavailable/failed units must prevent a complete-extraction claim.

Inputs and intermediates use generated filenames in a mode-0700 temporary directory. Input/derived files are mode 0600 and the directory is removed in `finally`. Executables and arguments are fixed; user asset IDs cannot become paths, commands or flags. PDF pages are rendered one at a time and original restrictions are preserved.

The Trigger image uses the official `aptGet` build extension with `tesseract-ocr`, `tesseract-ocr-eng` and `poppler-utils`; the package/lockfile and Trigger configuration are maintained separately. This adds no OCR subscription or external model request. Execution still consumes the existing Trigger compute allowance; actual cloud duration and total project usage must be measured. Each unit records `attempted: true` once Sharp/text/render/OCR work starts, preserving the flag even when a deadline produces a blocked outcome; preflight-only rejection remains false. Failed OCR attempts consume compute too. Worker/SQL accounting charges attempted units, and a catastrophic adapter exception marks unknown work so the entire remaining reservation is charged rather than inventing page evidence. This complements bounded job attempts and successful-page counters. No paid upgrade is authorized.

Run `node --import tsx --test tests/extraction-media.test.ts` for injected native-process fixtures with real image normalization. They are not live OCR. Run `node --import tsx scripts/probe-stage2-media.ts` for actual installed native tools against two visibly synthetic PNG slides, or add repeated `--file=private/path.png` / `--file=private/path.pdf` inputs. The probe performs no URL, model, database or calendar requests. Full OCR output stays ignored and private; reports contain hashes, per-unit outcomes and counts. Supplied-file source provenance and manual truth labels need separate evidence.
