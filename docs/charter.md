# FSU Opportunity Tracker charter

Verified project context: October 20, 2026; user timezone America/New_York. This local Git repository initially contained only Git metadata, an unborn `main` branch, no commits, no remote, no tracked files, and no repository-specific instructions. No application, database, cloud deployment, scheduler, or runtime integrations existed. Stage 0 files are the first project artifacts. No GitHub identity or repository URL was invented.

The tracker should help one FSU student discover worthwhile campus life early, retain a searchable review inbox, and recommend selectively. Coverage includes speakers, concerts, recitals, films, clubs, trips, social experiences and dates, research, employment visits, scholarships, and unfamiliar subjects. Selected Tallahassee opportunities supplement campus discovery. Personal relevance includes economics, policy/law, cities, real estate, GIS/data, research, national security, sustainability, music, culture, outdoors, engineering exploration, and ordinary college life.

Collection is broader than recommendations; recommendations are broader than calendar commitments. Routine events and basic tutorials can rank low while remaining searchable. Scarcity changes action urgency, not intrinsic quality. Factual card descriptions must not invent prestige, attendance, networking, food, eligibility, free entry, or ticket availability.

Events/programs, their individual occurrences, and ticket/registration/application milestones are separate records. Evergreen clubs and resources need no invented date. Unknown facts remain null; conflicts remain reviewable. A user may approve a ticket reminder without approving attendance. Each occurrence or milestone needs a separate approval transaction before a calendar outbox operation can exist.

Success is measured on audited sources and recorded windows, extraction labels, timeliness, and external-action correctness. The system cannot know the denominator of all campus activity. It must display access gaps and failed runs honestly. It cannot guarantee every Story, private club announcement, sellout warning, or event.

Stage 0 outcome: reproducible read-only evidence, an honest registry, data/adapter contracts, evaluation cases, explicit cost assumptions, and a bounded Stage 1 acceptance gate. Stage 0 does not deliver an operating tracker. No services have been purchased or provisioned and no user-facing alerts/calendar writes have been enabled.
