## Implemented path

`lib/instagram/collector.ts` makes one fixed-host Bearer-authenticated Graph v26.0 GET per due account. Each hourly overlap requests at most 25 parent posts, plaintext captions, canonical permalinks, publication timestamps and up to 20 ordered child IDs/types per carousel. Media files/URLs, Stories, OCR and event dates are not collected. Publication timestamps are not occurrence dates; posts remain separate from the event inbox.

The existing schedule is `0 * * * *` UTC, `window: "60m"`, concurrency one on Trigger Free. Core producers lease first in their own group; Instagram has an independent 16-source budget, two requests in flight, 10-second HTTP timeouts and a 90-second dispatch budget. Failed access records blocked health and a separate retry floor; it preserves last-success/cursors and prior posts. Persistence failures leave recoverable leases. This does not promise exact-hour observations or full history.

Migration 003, applied as hosted `20261021012900`, adds owner-only `instagram_updates`, append-only content versions and a security-invoker searchable current view. The service-only completion RPC writes run/captures/post changes/cursor/health atomically. Stable source/native IDs and content hashes prevent duplicate posts/versions; edits append versions. Private capture hashes refer to **sanitized API projection bytes**, not raw HTTP. Upload precedes the transaction, so interrupted commits can leave an orphan; production deletion remains disabled.

The authenticated `/instagram` feed searches captions, filters accounts and pages stable results. Captions render as escaped plaintext. Source enablement, attempts, successes, blocked status and freshness come from Supabase. A configured source, successful manual test or completed dispatcher is not evidence that every scheduled account collection succeeded.
